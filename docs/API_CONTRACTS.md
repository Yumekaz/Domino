# Domino API and integration contracts

This document describes the shared runtime contract in `packages/contracts/src/index.ts`, consumed by the API and frontend. The master specification remains authoritative. Current local acceptance is in [LOCAL_READINESS.md](LOCAL_READINESS.md); historical role sign-off records are separate from runtime verification.

## Runtime and errors

All routes are under `/api/v1`. Inputs and emitted payloads use shared Zod validation. IDs are UUIDs, revisions are full lowercase 40-character SHAs, timestamps are ISO 8601 and all repository paths are normalized relative paths. Errors use `{code, message, retryable, requestId?}` with an appropriate HTTP status. Secrets never belong in `VITE_` variables.

The server binds to `127.0.0.1:3000` by default. A non-loopback bind requires `DOMINO_API_TOKEN`; provide it in a Bearer authorization header. Browser origins must match `DOMINO_ALLOWED_ORIGINS` (defaults include localhost Vite ports 5173/5174). Current rate limiting is an in-memory 120 requests/minute/client protection per API process, not a distributed quota. The API body limit is 300 KB; repository responses from GitHub are capped at 1 MB. Requests use an exact `api.github.com` host, verified TLS, no redirects and a 15-second timeout.

`GET /health` reports database and queue status. It does not attest that a worker is running. API and worker startup require migrated PostgreSQL. `history.import` jobs are validated on both ends against their stored job record. App-job insertion and pg-boss enqueue occur in the same database transaction. Job reads reconcile a terminal queue state after a worker interruption; the last published snapshot remains available. An active import for a repository returns the existing job rather than starting a competing import. Reindex creates a fresh snapshot UUID even for an unchanged SHA; only ready/partial snapshots are published.

No repository-list or run-list endpoint is introduced. Search cursors bind the snapshot, query and last record. Risk cursors bind the snapshot and offset. Invalid/stale cursors are rejected instead of mixing revisions.

## Shared vocabulary

- Snapshot: `pending`, `ready`, `partial`, `failed`, `cancelled`. Job: `queued`, `running`, `ready`, `partial`, `failed`, `cancelled`. Analysis run: `queued`, `running`, `completed`, `partial`, `failed`, `cancelled`.
- Entity types and relationship types match master 6.1/6.2. Edge verification is `observed`, `derived`, or `inferred`; inferred edges are excluded by default. `observed` static imports are observations at the named SHA, not runtime guarantees.
- Q&A supports `supported`, `partial`, `not_found`, and `unavailable`. B's `interpretation` is explicitly mapped to wire value `inferred`. `unavailable` has a null answer, an error code and no claims. Shared validation checks citation membership, while B's server-side validator is responsible for source/claim support.
- Impact signals are `static_reverse_dependency`, `historically_coupled`, or `unknown`. A structural path starts at the affected file, ends at a changed file and contains depth + 1 entries. A historical association requires real `sampleSize`, `targetCommits`, `windowFrom` and `windowTo`; it does not become an import path. Truncation and limitations are explicit.
- Risk history dates and last edit may be null. Contributor counts represent observed history only; `commitCountIsLowerBound` exposes capped commit samples. Source entries are actual stored Git change edges. The response is paginated and never labels a multi-author file safe.
- PR analysis identifies full base/head SHAs, event, run status, freshness and real URLs. A nonterminal/stale/wrong-head report cannot contain an impact result. The worker revalidates PR identity and revisions before and after analysis. Repeated current-head input is idempotent; retry attempts cannot be overwritten by an old queue message. `actions_observed` identifies locally recomputed reports triggered by read-only observation, not imported remote results.

## B and C service boundaries

A's worker loads the integrated `createHistoryImportHandler`, `PostgresHistoryStore`, `PgSqlClient` and Octokit adapter from the merged B packages at runtime. It passes explicit `repoId`, `snapshotId`, GitHub ID, URL, branch and exact SHA. The A-owned `scopeHistoryStore` adapter stores immutable per-snapshot entity versions and uses them for source/graph reads and co-change observations. Identical content-addressed evidence IDs are allowed in different snapshots. B's `HistoryStore` remains its domain interface; A owns the migration and adapter.

`ImpactServicePort` and `PrCheckServicePort` are wired into the API. The import worker runs the pinned dependency-cruiser analyzer on the exact-SHA checkout and stores snapshot-scoped dependencies and source-backed `IMPORTS` edges before publication. Replacement is transactional and refuses published snapshots. Manual PR requests now enqueue `analysis.impact`; the registered worker invokes the same domain analysis against an isolated exact-head checkout and purpose-marked PR snapshot. Its publication is atomic with the report. The main history index is preserved. Removed files use imports remaining at the head; deleted dependents and historical co-change are explicitly outside this head-only analysis.

The separate read-only `pull_request` workflow produces its own step summary. Optional local observation reads successful public runs at `.github/workflows/pr-impact.yml`, verifies the current PR identity/head, and queues local recomputation with a genuine Actions URL. No remote artifact is trusted as an analysis result and no public event-ingestion route is added.

**Frontend coordination:** D now imports the shared Zod contracts, validates fixture data with that vocabulary, handles `unavailable` Q&A, nullable risk dates, typed terminal states, risk pagination/caveats and real co-change sample/window metadata. Vite proxies an optional server-side `DOMINO_API_TOKEN` without exposing it to the browser. A static production host still needs an equivalent reverse proxy.

## Known gates

Local acceptance includes real PostgreSQL/pg-boss imports, search/graph/risk, model-backed answers, exact-head manual PR analysis and read-only public Actions observation. See [LOCAL_READINESS.md](LOCAL_READINESS.md) and [LIVE_WORKSPACE_VALIDATION.md](LIVE_WORKSPACE_VALIDATION.md) for dated evidence and limits. Docker/hosted delivery are not signed off and are outside this local-only pass. Broad cross-engine, assistive-technology and repository-scale guarantees are not implied by the bounded local tests.
